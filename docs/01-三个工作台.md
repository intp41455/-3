# 01 · 三个工作台

三个工作台共用一个顶层 Tab 状态，切换时不销毁数据、不重新请求——所有内容都来自本地 `data/` 层。

```tsx
// src/App.tsx
const [currentTab, setCurrentTab] = useState<'presentation' | 'questionnaire' | 'workflow'>('presentation');
...
{currentTab === 'presentation'  && <PresentationViewer ... />}
{currentTab === 'questionnaire' && <QuestionnaireViewer />}
{currentTab === 'workflow'      && <MermaidWorkflow />}
```

> 默认 Tab 是 `presentation`——宣贯场景永远从「讲」开始。

---

## 一、宣贯演讲台（`PresentationViewer.tsx`）

### 数据源

`src/data/slidesData.ts` → `SLIDES_DATA: SlideData[]`，共 15 页。

### 页型驱动渲染

每页由一个必填的 `layout` 字段决定渲染分支，共 10 种：

| `layout` | 页型 | 消费的可选字段 |
|---|---|---|
| `cover` | 封面 | `cards`（汇报对象 / 版本周期） |
| `agenda` | 目录 / 要点 | `cards`（编号罗列） |
| `compare` | 左右对比 | `cards`（左 vs 右） |
| `matrix` | 维度矩阵 | `cards`（多维度平铺） |
| `flow` | 流程步骤 | `flowSteps` |
| `detail` | 要点卡片 | `cards` + `table` |
| `pyramid` | 金字塔层级 | `pyramidLevels` |
| `split` | 左右分栏 | `cards` |
| `gantt` | 甘特时间线 | `timeline` |
| `conclusion` | 结论与行动 | `cards` |

**设计意图**：新增一页时不需要写 JSX，只需在 `SLIDES_DATA` 里追加一个对象并选一个已有 `layout`。只有确实需要**新的视觉结构**时才去改组件加分支。

### 卡片配色

`SlideContentCard.type` 控制色系：

```ts
type?: 'primary' | 'secondary' | 'accent' | 'warning' | 'success'
```

### 逐字稿（`speakerNotes`）

**15 页全部带逐字稿，这是本模块的核心资产。**

它解决的是真实场景里的痛点：拿到一个漂亮的 PPT，但不知道该怎么讲——尤其当听众是汽车进出口板块的总经理这类**业务出身的高管**时，讲错了方向比不讲更糟。

逐字稿的写法是「口语陈述」，不是「要点复述」。例如第 1 页：

> 各位领导、各位同事，今天我们正式启动多智能体系统部署的前置调研工作。大模型落地的核心不是简单接入一个对话框，而是让 AI 智能体像数字员工一样融入我们的业务流程。在动工之前，我们需要一张详尽的「数字地形图」，这就是我们今天启动《信息采集标准问卷》的目的。

交互：
- 页面底部常驻展示当前页逐字稿
- 「复制逐字稿」按钮 → `navigator.clipboard.writeText(currentSlide.speakerNotes)`
- 顶栏「下载全套讲稿到本地」→ 导出全部 15 页讲稿的 Markdown

### 键盘与全屏

```ts
if (e.key === 'ArrowRight' || e.key === 'PageDown' || e.key === ' ') { /* 下一页 */ }
else if (e.key === 'ArrowLeft' || e.key === 'PageUp') { /* 上一页 */ }
else if (e.key === 'f' || e.key === 'F') { /* 全屏 */ }
```

全屏走 `containerRef.current?.requestFullscreen?.()`（带可选链，兼容不支持的环境）。

## 二、信息采集问卷（`QuestionnaireViewer.tsx`）

### 数据源

`src/data/questionnaireData.ts`：

```ts
QUESTIONNAIRE_METADATA   // 元信息 + 保密声明 + 填写须知
QUESTIONNAIRE_SECTIONS   // 10 部分 / 20 小节 / 78 问
```

### 查阅能力

| 能力 | 实现 |
|---|---|
| 全文检索 | 顶栏搜索框，覆盖维度标题、问题、说明、范例（placeholder 提示可用 `康源`、`API`、`SOP` 试搜） |
| 定位直达 | 左侧维度导航点击滚到对应章节 |
| 复制全文 Markdown | `generateFullMarkdown()` → clipboard |
| 下载 Markdown | `generateFullMarkdown()` → `triggerDownload()` |

### Markdown 生成

`generateFullMarkdown()` 在组件内拼装——它遍历 `QUESTIONNAIRE_METADATA` 与 `QUESTIONNAIRE_SECTIONS`，输出带标题层级、维度分隔、问题 + 说明 + 范例的结构化文本。**下载与复制共用同一个生成函数**，保证两条通道产物一致。

## 三、协同流程图（`MermaidWorkflow.tsx`）

### 双数据源结构

这个模块有**两份互相独立的数据**：

| 常量 | 类型 | 用途 |
|---|---|---|
| `RAW_MERMAID` | `string` | Mermaid `graph TD` 源码，用于渲染可视化流程图 + 提供「复制源码」 |
| `STEPS` | `StepNode[]` | 9 个步骤的详细卡片（角色 / 阶段 / 交付物 / 风险提示） |

> ⚠️ **两份数据需要手工同步**。改流程时若只改 `RAW_MERMAID`，卡片区会与实际流程图不一致。这是当前架构的一个已知成本，见 [docs/03](03-数据层与问卷规范.md)。

### 流程图结构要点

`graph TD` 里有一个**回退分支**——这是流程设计的关键：

```mermaid
F[✅ 内部交叉审核与质检] --> G{指标与接口是否完备？}
G -->|否 需补充| D[📝 各部门分头填写对应模块]
G -->|是 确认无误| H[📎 附上历史台账与接口数据附件]
```

**质检不通过要退回填报环节**，而不是带病往下走。很多企业的调研流程缺这个回环，导致「收上来的问卷其实没法用，但流程上已经算完成了」。

### `StepNode` 四要素

```ts
interface StepNode {
  id: string;
  code: string;             // 'STEP 01'
  title: string;
  role: string;             // 谁负责——避免责任真空
  desc: string;
  phaseId: 'phase1' | 'phase2' | 'phase3' | 'phase4';
  phaseName: string;
  deliverable: string;      // 产出什么——避免"填了但不知道要交什么"
  riskNote: string;         // ★ 这一步容易怎么翻车
}
```

`riskNote` 是本模块最有价值的设计。它不是「注意事项」，而是**把失败模式直接写出来**：

| 步骤 | riskNote |
|---|---|
| STEP 01 问卷正式发放 | 必须同步附带高管宣贯讲话要点，避免被业务部门当作普通例行公事而忽视。 |
| STEP 02 指定单一问卷总协调人 | 切忌多头汇报或未设总接口人，否则跨部门协作极易出现责任真空与推诿。 |
| STEP 03 分解派发至各业务与 IT 部门 | 各认领人需由部门主管背书，确保填报人为熟悉一线业务与系统的骨干专家。 |

### 复用方式

「一键复制 Mermaid 源码」按钮把 `RAW_MERMAID` 写入剪贴板。丢进飞书文档 / Notion / Obsidian / GitHub Markdown 都能直接渲染成图——**不需要让对方也打开这个应用**。

## 三个工作台的关系

```text
        ┌──────────────────────────────────────────┐
        │  宣贯演讲（15 页 + 逐字稿）                 │
        │  作用：让管理层理解为什么值得做、要什么支持      │  ← 先讲
        └────────────────┬─────────────────────────┘
                         │ 讲完发问卷
        ┌────────────────▼─────────────────────────┐
        │  信息采集问卷（10 维度 78 问）              │  ← 再填
        │  作用：把业务事实、数据、口径、约束收上来       │
        └────────────────┬─────────────────────────┘
                         │ 填报需要流程保障
        ┌────────────────▼─────────────────────────┐
        │  协同流程图（4 阶段 9 步）                  │  ← 后管
        │  作用：谁填、什么时候交、交什么、怎么算合格     │
        └──────────────────────────────────────────┘
```

三者的导出件（Slides / Markdown / Mermaid / 离线 HTML）可以**完全不依赖本应用**地在企业内流转——这是刻意的设计：工具的价值在于产出可流转的交付物，而不是把人绑在工具里。
