
**这是 Google AI Studio 创建应用时自动生成并提交的标准做法**，其内容属于「公开客户端配置」。

### 关于 Firebase Web API Key 的性质（重要）

| 常见误解 | 实际情况 |
|---|---|
| 「这个 API Key 泄露了，别人就能读写我的数据」 | ❌ 不成立。Firebase Web API Key **按设计就是公开的**——它以明文形式出现在任何 Firebase Web 应用的 HTML/JS 里 |
| 「那它有什么用」 | ✅ 它只是**标识项目身份**，不是身份凭据。真正的访问控制由 **Firebase 安全规则**（Firestore/Storage Rules）和 **OAuth 授权来源白名单**（Authorized origins）执行 |

**结论**：该文件可以安全地保留在公开仓库中。但**这不代表不需要防护**——见下文第四节。

> 若仓库是私有的，且你希望进一步减少暴露面，可以把此文件改为从环境变量注入。代价是增加部署配置复杂度，收益有限。

## 二、OAuth 作用域（授权范围）

`src/services/auth.ts` 申请的权限：

| 作用域 | 授权范围 | 敏感度 |
|---|---|---|
| `openid` / `email` / `profile` | 基础身份（Firebase Auth 默认附带） | 低 |
| `https://www.googleapis.com/auth/presentations` | **Google Slides 全部演示文稿的读写** | ⚠️ 高——可读写用户账号下**所有** Slides 文件 |
| `https://www.googleapis.com/auth/drive.file` | 仅限**本应用创建**的 Drive 文件 | 低——设计上就是最小权限 |

### ⚠️ 值得复核的一点：`presentations` 是全域作用域

`https://www.googleapis.com/auth/presentations` 授权后，应用**理论上可以读写该 Google 账号下所有演示文稿**，而本应用的实际需求只是「创建一份新文稿并写入内容」。

**最小权限替代方案**：Google 提供 `https://www.googleapis.com/auth/drive.file` 单独使用时，对本应用创建的文件即可写入。若只需「创建并写入自己新建的文件」，可尝试**去掉 `presentations` 作用域**，仅保留 `drive.file`。

这在实践中不一定可行（Slides API 对 `drive.file` 的支持视接口而定），需要实测。但**在提交 Google OAuth 应用审核时，作用域越少越容易过审**——这直接影响本项目能否从「测试模式」转为可公开发布。

**建议动作**：实测仅用 `drive.file` 时 `presentations.create` 与 `batchUpdate` 是否可用；若可用，删掉 `presentations`。

## 三、令牌处理

### 当前实现

```ts
let cachedAccessToken: string | null = null;   // 模块级内存变量
```

| 属性 | 现状 |
|---|---|
| 存储位置 | **内存**，不落 localStorage / sessionStorage / cookie |
| 生命周期 | 页面存活期间；刷新即失效 |
| 传输方式 | 仅作为 `Authorization: Bearer` 头，直达 `*.googleapis.com` |
| 是否经过第三方服务器 | ❌ 无——所有 API 调用从浏览器直接发往 Google |

**这是一个正确的安全取舍**：令牌不落盘，XSS 也无法通过读 localStorage 拿到持久令牌。代价是刷新需重登。

### 反面做法（不要做）

```ts
// ❌ 绝对不要这样
localStorage.setItem('google_token', accessToken);
```

把 OAuth access token 写进 localStorage 会让任何一次 XSS 都能窃取长期有效的 Google Slides / Drive 权限。

### 若需要「刷新不掉登录」

正确路径是重新走一次授权，而不是持久化令牌：

- 前端的 `reauthenticateWithPopup(auth, provider)`（需用户手势触发）
- 或引入后端：用 authorization code 换 refresh token，refresh token 存服务端加密存储，前端只拿短期 token

## 四、生产化前必须收紧的项

| 优先级 | 项 | 具体动作 |
|---|---|---|
| **P0** | Google Cloud 项目里对 API Key 加限制 | 在 Google Cloud Console → API 和服务 → 凭据，把该 API Key 限制为**仅允许必要 API**（Identity Toolkit 等），并设置**HTTP 来源限制**（你的域名） |
| **P0** | 配置 OAuth 授权来源白名单 | Authorized JavaScript origins / redirect URIs 只填你的域名，不要留 `localhost` 或通配 |
| **P1** | 复核 `presentations` 作用域是否必要 | 见第二节 |
| **P1** | 启用 Google Slides API / Drive API 并设置配额告警 | 防止被刷爆配额 |
| **P1** | 若启用 Firestore/Storage：**必须**配置安全规则 | 默认的测试规则（`allow read, write: if true`）等于裸奔 |
| **P2** | OAuth 同意屏幕填写完整的应用信息与隐私政策 | 否则无法通过验证、用户会看到「未验证的应用」警告 |
| **P2** | 移除仓库中的真实企业信息 | 问卷范例含康源集团的真实数据（机构分布、营收、系统清单），公开仓库建议替换为脱敏示例 |

## 五、内容安全

### 导出内容的 XSS 风险

本应用会生成 Markdown 与独立 HTML 文件并触发下载：

| 导出物 | 风险 | 现状 |
|---|---|---|
| `.md` | 低——纯文本 | 内容全部来自本地 `data/`，无外部输入 |
| `.html` | 中——若将来引入用户输入并直接拼接，会有注入风险 | 当前全部内容来自硬编码数据层，**无用户可控输入** |
| Google Slides | 低——文本通过 API 写入，不经过 HTML 渲染 | 同上 |

**当前无注入面**（所有内容都是编译期常量）。但如果将来加入「用户自定义标题 / 备注」这类输入，**必须**对拼接进 HTML 的值做转义。

### 问卷数据的保密

问卷本身携带保密声明：

> 本问卷所涉及的企业数据（包括但不限于组织架构、运营数据、财务信息、人员信息等）仅用于本次多智能体系统方案设计。未经贵方书面许可，不得向任何第三方披露或在其他项目中使用。所有数据在方案交付后进行加密归档或按约定销毁。

**技术层面的现状**：本应用**不存储任何填报数据**——它只提供空的问卷模板供下载。填报结果由企业以文件形式回传，不在本系统的责任范围内。

这一点需要在交付时向对方明确：**问卷模板工具 ≠ 数据收集平台**。如果确实需要在线收集，那需要另外设计带权限与加密的数据存储方案，不能复用本应用。
